## 宿題

- 取り組んだレベル：発展（a）ADK で作り直す
- やったこと：
  - `adk_agent/glossary_agent/` に、組み立て部分だけを ADK（google-adk 2.14.0）で書き直したエージェントを作った。`INSTRUCTIONS`・3つのツール・モデル（`gemini-3.5-flash-lite`）は演習と同じものを使った。ADK は固定依存に入れず `uv run --with google-adk` で動かした
  - 宿題の問いを「モデル・指示・ツールを固定し、ハーネス（組み立てて動かす部分）だけを替えたとき、何が変わり何が変わらないか」と捉えた。次の4点を調べた
    1. 同じ質問を両方で繰り返し実行し、ツール呼び出しと LLM 呼び出し回数を比べた
    2. 実際にモデルへ送られるリクエストを API を呼ばずに取り出し、比べた
    3. 続けて質問したときに、前の会話を覚えているかを比べた
    4. `--trace`・`adk run`・`adk web` での見え方を比べ、Pydantic 側の Web 画面（`to_web()`）と Logfire についてドキュメントを調べた
  - `adk run` ではツール呼び出しが見えないので、`--trace` と同じ形式で出す `scripts/adk_trace.py` を作った
- 結果：

  **書き方**

  | 観点 | Pydantic AI | ADK |
  |---|---|---|
  | 指示 | `Agent(instructions=...)` | `Agent(instruction=...)` |
  | ツール | 作ったあとで `agent.tool_plain(関数)` を1つずつ登録 | 作るときに `tools=[関数, ...]` でまとめて渡す。どちらも docstring と型ヒントから説明を作る |
  | モデル | 実行時に渡す（テストで `TestModel` に差し替えられる） | ふつうは定義時に `model=` で書く |
  | 名前 | 不要 | `name` が必須 |

  **振る舞い（同じ質問を各3回）**：ツールの選び方・引数・LLM 呼び出し回数（すべて2回）は、18回とも両者で一致した。用語集にない「RLHF」には、6回とも推測で答えず「用語集にない」と返した。ただし LoRA/QLoRA の質問を回数を増やして実行すると、ADK では23回中4回、QLoRA を検索せずに自分の知識で答えた（Pydantic AI は13回中0回）。偶然でもこの程度の差は出うる（Fisher の正確検定 p=0.15）ので、フレームワークの差とは言えない。送る中身が同じでも揺れるのは、モデル自体の揺らぎによる

  **ハーネスがコンテキストに足すもの**：ADK は指示文の末尾に `You are an agent. Your internal name is "glossary_agent".` を自動で足し、ツールの引数スキーマに `title` を付けていた。Pydantic AI はツール呼び出しをスキーマに合わせる設定（`function_calling_config.mode = VALIDATED`）を送っていた。ツールの戻り値は、どちらも辞書に包んで渡す（キー名が `result` と `return_value` で違う）。この差により、入力トークンは毎回決まって ADK が 9〜14% 多かった（例：LoRA/QLoRA で 1426 → 1550）

  **会話の履歴**：「LoRAとは？」のあとに「さっき私が質問した用語は？」と聞いた

  | 構成 | 回答 | 入力トークン |
  |---|---|---|
  | ADK の同じセッション（`adk run`・`adk web` と同じ） | LoRA | 929 |
  | Pydantic AI に履歴を渡す（`message_history`） | LoRA | 892 |
  | Pydantic AI に履歴を渡さない（演習の `app.agent` と同じ） | 「質問された用語はありません」 | 434 |

  **見え方**

  | | 見えるもの |
  |---|---|
  | Pydantic AI `--trace`（演習） | 終了後に、ツール名・引数・戻り値の先頭と `requests` をテキストで表示 |
  | `adk run` | 回答だけ。ツール呼び出しは画面にもログにも出ない |
  | `adk web` | 会話の中にツール呼び出しと戻り値が並ぶ。Traces タブで LLM 呼び出しとツール実行を時間軸で見られる（例：LLM 1.02秒、ツール 0.5ミリ秒、LLM 3.51秒）。エージェントとツールの構成図、Evals（評価）もある |
  | Pydantic AI `to_web()` | 開発用のチャット画面。ツール呼び出しは「`search_glossary x2 done`」とまとめて出る。時間や LLM 呼び出し回数は出ない |

  Pydantic AI 側でトレースを見る道具は Logfire（Pydantic 社のサービス）である。Pydantic AI は実行・LLM 呼び出し・ツール呼び出しを OpenTelemetry のトレースとして出力し、Logfire で表示する設計になっている（公式ドキュメント）。Logfire はクラウドで、無料枠は GitHub ログインで使える。セルフホストは Enterprise プランに限られ、ローカルには立てられない。Logfire の画面は試していない

- 気づき・疑問：
  - 振る舞いを決めているのは、フレームワークよりもモデル・指示文・ツールの説明文だった。ハーネスが決めるのは、コンテキストに何を足すか（費用）、履歴を持つか、どう見えるかである。講義の「エージェント＝モデル＋ハーネス」「ハーネスで費用が変わる」を、小さな規模で確かめられた
  - 1回の実行では「同じ」とは言えない。最初は各1回の結果を見て「ツールの呼び方は同じ」と書いたが、回数を増やすと揺れが見えた。比べるときは繰り返して分布で見る必要がある
  - INSTRUCTIONS の「必ず用語集を確認する」は毎回は守られなかった。確実に守らせたいなら、用語をすべて検索したかをハーネス側のコードで確かめる必要がある（講義の「完了は言葉ではなく状態で確かめる」と同じ考え方）
  - ADK が指示を1行足していることは、コードを読むだけではわからず、実際に送られたリクエストを見て初めて気づいた
  - 履歴を持つかどうかはライブラリではなく、使う側のプログラムで決まる。履歴を持つと入力トークンが約2倍になり、講義の「チャットは毎回全文を送り直している」を数字で確かめられた
  - Google は ADK と `adk web`、Pydantic は Pydantic AI と Logfire をセットで提供している。開発者向けの画面を手元に持つか、クラウドのサービスに任せるかが設計の違いだと感じた。Logfire の画面で `adk web` と同じように比べるのは、まだできていない
